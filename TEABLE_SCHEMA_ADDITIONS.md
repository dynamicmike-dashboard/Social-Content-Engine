# Teable Schema Additions Required for Live Integration

These tables and fields must be created in Teable before the live integration works.
Field IDs will be generated by Teable - update the API code with actual IDs after creation.

## 1. Generation Jobs Table
**Suggested Name:** `Generation Jobs`
**Purpose:** Durable state for AI content generation workflows

| Field Name | Type | Options |
|---|---|---|
| Job ID | Formula | RECORD_ID() |
| Client ID | Link (many-to-one → Clients) | Required, lookup Client Users |
| Request Type | Single Select | MONTHLY_PLAN, POST_REGENERATION |
| Content ID | Link (many-to-one → Content Calendar) | Optional, only for POST_REGENERATION |
| Period Start | Date | Date only, UTC |
| Period End | Date | Date only, UTC |
| Status | Single Select | QUEUED, RUNNING, SUCCEEDED, PARTIAL, FAILED, CANCELLED |
| Idempotency Key | Single Line Text | Unique, indexed |
| Input Revision | Long Text | Hash of questionnaire responses used |
| Expected Posts | Number | Default 30 |
| Completed Posts | Number | Default 0 |
| Failed Posts | Number | Default 0 |
| Attempt Count | Number | Default 0 |
| Error Summary | Long Text | |
| Provider Job ID | Single Line Text | External queue job ID |
| Created At | Created Time | |
| Updated At | Last Modified Time | |

**Views needed:**
- By Client (group by Client ID)
- By Status (kanban by Status)
- Pending Jobs (filter: Status in QUEUED, RUNNING)
- Failed Jobs (filter: Status = FAILED)

## 2. Client Memberships Table (if not using existing auth org model)
**Suggested Name:** `Client Memberships`
**Purpose:** Maps verified auth identities to client records

| Field Name | Type | Options |
|---|---|---|
| Membership ID | Formula | RECORD_ID() |
| Client ID | Link (many-to-one → Clients) | Required, lookup Client Users |
| Auth Issuer | Single Line Text | e.g., "clerk", "auth0", "custom" |
| Auth Subject | Single Line Text | Auth provider's user ID (sub claim) |
| Role | Single Select | CLIENT, AGENCY_ADMIN |
| Status | Single Select | INVITED, ACTIVE, REVOKED |
| Teable User | User | Optional, for direct Teable access |
| Created At | Created Time | |
| Updated At | Last Modified Time | |

**Constraints:** Unique on (Auth Issuer, Auth Subject, Client ID)
**Views needed:**
- Active Memberships (filter: Status = ACTIVE)
- By Client (group by Client ID)

## Permission Role Updates Required

After creating the above tables/fields, update the **Client** permission role:

1. **Generation Jobs**: Client role can READ own jobs (filter by Client ID)
2. **Client Memberships**: Client role can READ own membership (filter by Client ID)
3. **Content Calendar**: Add edit access to new generation fields
4. **Content Assets**: Add edit access to Asset Order
5. **Approval Activity**: Add read access to new actor fields

**Important:** The Client permission role activation must be completed in Teable (was not run in previous session). Run the enable command before granting collaborator access.
